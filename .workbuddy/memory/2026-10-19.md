## HTTP 代理访问控制（httpAuthHeader / httpAuthPagePath / allowIPs）

按 `doc/http_access_control.md` 规格在 frp2 仓库落地三个 http 代理访问控制能力：

- 新增 `pkg/util/vhost/ip_filter.go`（`IPAllowList`，netip 解析 IP/CIDR，IPv4-mapped 归一化，解析失败 fail-closed）
- 新增 `pkg/util/vhost/auth_page.go`（登录页 `/.auth/login|logout`、HMAC-SHA256 签名 Cookie `frp_auth_<16hex>`、12h TTL、Cookie 剥离、开放重定向防护）
- `pkg/util/vhost/http.go`：请求处理顺序改为 IP 白名单 → 登录页 → 鉴权 → 转发；自定义鉴权头；转发前剥离鉴权头与 frp 会话 Cookie；401/407/302 分流
- `pkg/util/vhost/vhost.go`：`RouteConfig` 增加 `AuthHeader` / `AuthPagePath` / `AllowList`
- `pkg/config/v1/proxy.go`、`pkg/msg/msg.go`：新增 TOML/JSON 字段与 `http_auth_header` / `http_auth_page_path` / `allow_ips` 控制消息字段
- `pkg/config/v1/validation/proxy.go`：配置加载期校验（头名合法性、路径合法性、IP/CIDR 合法性）
- `server/proxy/http.go`：组装 `RouteConfig`，非法 allowIPs 直接让代理启动失败
- 同步 `doc/http_access_control.md`、`doc/nginx_frp_auth.example.conf`，并在 `conf/frpc_full_example.toml` 增加注释示例

约定/注意：
- 该仓库工作区为 CRLF（`core.autocrlf=true`），新增文件也写为 CRLF；判断 gofmt 需先转 LF 再看。
- `go build ./...` 会因 `web/frpc|frps` 缺 `dist` 而失败（需先 `make web`），验证时用 `./pkg/... ./server/... ./client/...`。
- `routeByHTTPUser` 仍只从 `Authorization`/`Proxy-Authorization` 取用户名，与自定义鉴权头无关（与文档一致）。
- `web/frpc` 前端表单未包含这三个字段，Web UI 编辑代理会丢弃它们（已知限制）。

## 交叉编译产物（release/）

需求：linux-amd64、linux-armv7、windows-amd64。做法：

- 先 `cd web && npm ci` + `npm run build --workspace frps|frpc` 生成 `web/*/dist`，再不带 `noweb` 标签编译，dashboard 才会嵌入；只想要核心功能可用 `-tags "frps,noweb"`。
- 命令模板：`CGO_ENABLED=0 GOOS=<os> GOARCH=<arch> [GOARM=7] go build -trimpath -ldflags "-s -w" -tags frps|frpc -o release/frps_<suffix> ./cmd/frps`；windows 加 `.exe`。
- 命名：`frps_{linux_amd64,linux_armv7,windows_amd64.exe}`，arm 用 GOARM=7（上游发布名为 `linux_arm_hf`，此处按平台语义改名 armv7）。
- 坑：bash 里用 `set -- $spec` 拆参数时空字段会被吞掉，导致输出名变成 `release/frps_`；要显式赋值。
- 本机默认带 `HTTP_PROXY`，本地联调 curl 必须加 `--noproxy '*'`；且后台进程需在同一次 Bash 调用内启动+验证，否则会被回收。
- 联调结论（windows 版 frps+frpc，authHeader=X-FRP-Auth，pagePath=/_o7k2/entry）：浏览器导航 302→登录页、API 401 无 WWW-Authenticate、错误密码 401、正确密码 302+Set-Cookie、带 Cookie 200、自定义头 200、仅 Authorization 401、::1 在 allowIPs 内可访问。
