## 交叉编译产物（release/）

需求：linux-amd64、linux-armv7、windows-amd64。做法：

- 先 `cd web && npm ci` + `npm run build --workspace frps|frpc` 生成 `web/*/dist`，再不带 `noweb` 标签编译，dashboard 才会嵌入；只想要核心功能可用 `-tags "frps,noweb"`。
- 命令模板：`CGO_ENABLED=0 GOOS=<os> GOARCH=<arch> [GOARM=7] go build -trimpath -ldflags "-s -w" -tags frps|frpc -o release/frps_<suffix> ./cmd/frps`；windows 加 `.exe`。
- 命名：`frps_{linux_amd64,linux_armv7,windows_amd64.exe}`，arm 用 GOARM=7（上游发布名为 `linux_arm_hf`，此处按平台语义改名 armv7）。
- 坑：bash 里用 `set -- $spec` 拆参数时空字段会被吞掉，导致输出名变成 `release/frps_`；要显式赋值。
- 本机默认带 `HTTP_PROXY`，本地联调 curl 必须加 `--noproxy '*'`；且后台进程需在同一次 Bash 调用内启动+验证，否则会被回收。
- 联调结论（windows 版 frps+frpc，authHeader=X-FRP-Auth，pagePath=/_o7k2/entry）：浏览器导航 302→登录页、API 401 无 WWW-Authenticate、错误密码 401、正确密码 302+Set-Cookie、带 Cookie 200、自定义头 200、仅 Authorization 401、::1 在 allowIPs 内可访问。

## 体积裁剪：删除 quic/kcp 传输、Prometheus、OIDC、SSH 隧道、虚拟网

用户嫌 frps 19MB 太大，确认"只保留 tcp"属实后继续裁剪（用户选定全部四项）：

- 传输层：删除 quic-go（frps/frpc 的 quic 通道、HandleQUICListener、QUICOptions）与 kcp 监听（ListenKcp/UDP 工具）。frpc↔frps 仅剩 tcp/websocket/wss。
- 监控：删除 pkg/metrics/prometheus 与 /metrics 路由、enablePrometheus 配置（mem 统计保留，dashboard 仍有流量数据）。
- 认证：删除 OIDC（pkg/auth/oidc*、auth.oidc.* 配置、go-jose/oauth2 依赖），仅剩 token（含 tokenSource）。
- SSH 隧道网关 + 虚拟客户端：删除 pkg/ssh、pkg/virtual、msg.ClientSpec、sshTunnelGateway 配置、internal 免 TLS/免鉴权通道。
- 虚拟网卡：删除 pkg/vnet、virtual_net 插件、virtualNet/featureGates 配置（featuregate 包整个删除）。
- 依赖清理后二进制内不再包含 quic-go、prometheus、go-jose、oauth2、water/wireguard。

体积（-s -w，嵌入 dashboard）：
- frps：20.10MB（最初）→ 19.06MB（仅 tcp 代理后）→ **12.78 MB**（本轮后）
- frpc：16.27MB → 15.74MB → **14.23 MB**

剩余大头：Go 运行时+net/http+crypto 栈、kcp-go（经 fatedier/golib/net 的 protocol dial 间接引入，约 1.5MB，需 patch golib 才能去掉）、k8s.io/apimachinery（仅用于 annotation 名校验 IsQualifiedName，可换本地实现省约 0.5MB）、web dashboard（约 0.5MB，noweb 可去）。

验证：go build ./...、go vet ./...、单测全绿；e2e 需要 bin/frps.exe|frpc.exe（Windows 上 make 产物无 .exe 后缀，需复制一份 .exe 才能被 e2e exec）。

补充：e2e 跑通后暴露并修复一处真实 bug——python 块删除 `case *msg.NewVisitorConn:` 时把随后的 `default:` 标签一起删了，导致 handleConnection 里 NewWorkConn 分支无条件执行 log+conn.Close()，所有 work connection 建立刻断、代理全挂。教训：用脚本删 switch case 时，锚点应取 case 关键字本身、结束点要看下一行标签是否被吞。

e2e 在 Windows 本机剩余失败原因（与代码无关）：① 测试模板把 `C://...` 反斜杠路径写进无扩展名配置文件，TOML 因非法转义失败后按 YAML 读取，整份配置被当成字符串（"cannot unmarshal string into Go value of type v1.ServerConfig"）；② 本机 HTTP_PROXY 让 frpc 走代理连 127.0.0.1 报 502。Linux CI 上路径是 /tmp/... 不受影响。
