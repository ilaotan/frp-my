## 交叉编译产物（release/）

需求：linux-amd64、linux-armv7、windows-amd64。做法：

- 先 `cd web && npm ci` + `npm run build --workspace frps|frpc` 生成 `web/*/dist`，再不带 `noweb` 标签编译，dashboard 才会嵌入；只想要核心功能可用 `-tags "frps,noweb"`。
- 命令模板：`CGO_ENABLED=0 GOOS=<os> GOARCH=<arch> [GOARM=7] go build -trimpath -ldflags "-s -w" -tags frps|frpc -o release/frps_<suffix> ./cmd/frps`；windows 加 `.exe`。
- 命名：`frps_{linux_amd64,linux_armv7,windows_amd64.exe}`，arm 用 GOARM=7（上游发布名为 `linux_arm_hf`，此处按平台语义改名 armv7）。
- 坑：bash 里用 `set -- $spec` 拆参数时空字段会被吞掉，导致输出名变成 `release/frps_`；要显式赋值。
- 本机默认带 `HTTP_PROXY`，本地联调 curl 要用 `env -u HTTP_PROXY -u http_proxy ...` 绕过；后台进程需在同一次 Bash 调用内启动+验证，否则会被回收。
- 联调结论（windows 版 frps+frpc，authHeader=X-FRP-Auth，pagePath=/_o7k2/entry）：浏览器导航 302 跳登录页、API 401 且无挑战头、错误密码 401、正确密码 302 并下发会话 Cookie、带 Cookie 200、自定义头 200、仅 Authorization 401、::1 在 allowIPs 内可访问。

## 代理类型的鉴权能力边界（实测）

- `type = "tcp"`：`TCPProxyConfig` 只有 `remotePort`，无任何 http 用户名密码字段，纯 TCP 无 HTTP 头可承载凭据。
- `type = "tcpmux"` + `multiplexer = "httpconnect"`：`TCPMuxProxyConfig` 有 `httpUser/httpPassword`，由 muxer 校验 `Proxy-Authorization`。实测无凭据/错误凭据均返回 407，正确凭据可透传到源站；frps 需配 `tcpmuxHTTPConnectPort`，客户端必须走 HTTP CONNECT（curl 用 `-p -x`，ssh 用 ProxyCommand）。
- `allowIPs`、`httpAuthHeader`、`httpAuthPagePath` 只作用于 `type = "http"`，tcpmux/tcp 不支持。
- `allowUsers` / `sk` 属于 `stcp`/`xtcp` 访问者模型，不适用于 tcp。

## TCP 后端拿真实客户端 IP：PROXY protocol（实测）

- 现象：tcp 代理后端看到源 IP 恒为 127.0.0.1，因为 frpc 是本地新建连接访问 `localIP:localPort`，TCP 层无法改写源地址。
- 解法：frpc 侧给代理开 `transport.proxyProtocolVersion = "v1"|"v2"`（两种写法均可：`[proxies.transport]` 子表，或 `[[proxies]]` 内 dotted key），frpc 会在连到本地服务后先写 PROXY 头，内容取自 frps 观察到的 `m.SrcAddr/SrcPort`（见 `client/proxy/proxy.go` 的 `ProxyProtocolVersion` 分支）。
- 实测（本地 v2）：后端收到 `PROXYv2 ver_cmd=0x21 fam=0x11 src=127.0.0.1:62207 dst=127.0.0.1:17095`，src 端口与客户端 `getsockname()` 的 62207 完全一致，证明携带真实来源。
- 实测（本机网卡 172.26.5.104，更具说服力）：客户端 `local endpoint 172.26.5.104:62441`，后端内核层 peer 仍是 `127.0.0.1:62442`（frpc 回环连接），但 PROXYv2 头里是 `src=172.26.5.104:62441 dst=172.26.5.104:17195`；关闭该选项后无头、直接是业务数据 `hello`。
- 约束：后端必须能解析该头（nginx `listen ... proxy_protocol` + `real_ip_header proxy_protocol`；HAProxy `accept-proxy`），否则会把头当业务数据；sshd 原生不支持，需前面套 HAProxy 或放弃。




## tcp 代理防滥用手段（代码层面已核实）

- `auth.token` / `authentication_method` 只保护 frps 不被陌生 frpc 接入，**不限制访问者连接 remotePort**，常被混淆。
- frp 对 `type = "tcp"` 没有来源 IP 白名单（`allowIPs` 是 http vhost 层），IP 限制只能靠云安全组/iptables 或前置 nginx stream/haproxy。
- 官方意义上的“私密 TCP”：`stcp`/`sudp`/`xtcp` + `secretKey`，不监听公网端口；`allowUsers` 为空时默认只允许同一 frpc `user` 访问（见 `server/proxy/proxy.go` startVisitorListener）。
- 管理员侧限制：`allowPorts`（PortsRange start/end/single）、`maxPortsPerClient`、`transport.maxPoolCount`、`transport.heartbeatTimeout`。
- 加密：frps `transport.tls.force = true` 强制 frpc 走 TLS，避免 token 明文。
- 可观测：frps 在 info 级别打印 `get a user connection [ip:port]`（server/proxy/proxy.go:260），可作为 fail2ban 的日志源。
- 限速：代理级 `transport.bandwidthLimit` + `bandwidthLimitMode = "server"`（服务端限速，客户端改不掉）。
